# 瓮城控制面板 · 分类折叠（v2.6.2）

> 目标：母体控制面板里的「项目 & 任务 & 对话」不再混成一列，而是按
> **进行中 / 已归档 / 临时** 三组折叠展示；进行中的对话先显示 7 条，归档与临时默认收起。
> 本次只是 `client.js` 的 UI 层改动：**不改协议、不改接口、不改运行时的数据语义**。

## 1. 三组规则

| 分组 | 左栏：母体「项目 & 对话」 | 右栏：分身「任务 & 项目」 | 默认状态 |
|---|---|---|---|
| **进行中** | 不是归档、也不是空会话的对话（按工作区分组） | `status !== archived` 且不是快速派生任务的任务卡片 | **展开** |
| **已归档** | `session.archived = true` 的对话（按工作区分组） | `status = archived` 的任务 | **折叠** |
| **临时** | `session.empty = true` 的空会话（没有用户消息，无法继续开发） | 快速派生任务（标题为 快速派生 / 双击快速派生 / 徽标快速派生 / 重试快速派生，空白且未继承会话） | **折叠** |

判定优先级：**归档 > 临时 > 进行中**——同一项即使同时 `archived` 且 `empty`，也只出现在「已归档」，不重复计数。

> 「临时」为什么这样定义：宿主没有 `temporary` 字段，也不该为了 UI 改协议。这里只用宿主已返回的
> 事实（`archived`、`empty`、任务标题），并在分区标题的 tooltip 里写明。定义变化只影响这一个文件。

## 2. 进行中只显示 7 条

- 左栏「进行中」分组最多先渲染 **7 条会话**（`PANEL_ACTIVE_LIMIT = 7`），按工作区分组展示；
- 超出部分折叠，分区标题右侧出现「展开剩余 N 个」按钮；展开后按钮变为「收起多余会话」；
- 被折叠时在列表末尾提示「进行中会话只显示前 7 个，其余 N 个已折叠」；
- 进行中的计数仍是**总数**（不是当前可见数），避免看起来像丢数据。

## 3. 临时内容可整组隐藏

- 顶栏按钮「隐藏临时内容 / 显示临时内容」切换整组显示；
- 偏好写入 `localStorage["fang.panel.showTemporary"]`，下次打开面板沿用；storage 不可用（隐私模式）时只影响本次面板会话；
- 隐藏后：不渲染临时分区、不计入可见计数（左栏 Pill 显示「临时已隐藏」提示）；
- 如果隐藏后没有任何其它内容，显示空态「当前只有 N 条临时内容（已隐藏）」+「显示临时内容」按钮，
  不让人误以为数据丢了。

## 4. 计数与文案

- 左栏 Pill tooltip：`进行中 X · 已归档 Y · 临时 Z`（临时隐藏时显示「临时已隐藏」）；
- 右栏 Pill tooltip：`进行中 X 个，已归档 Y 个，临时 Z 个`；
- 归档/临时标题上带数量；折叠标题可点击（键盘可达，`aria-expanded`）；
- 同一工作区同时存在进行中/已归档/临时会话时，会在对应分区各出现一次；折叠状态按
  `分区:工作区` 独立记忆，互不串扰。

## 5. 代码位置

| 位置 | 作用 |
|---|---|
| `client.js` `PANEL_TEMP_PREF_KEY` / `PANEL_ACTIVE_LIMIT` / `QUICK_DERIVE_TITLE_RE` | 偏好 key、7 条上限、临时任务标题判定 |
| `classifyMotherSessions()` / `classifyTasks()` | 纯分类函数（归档 > 临时 > 进行中） |
| `readPanelBoolPref()` / `writePanelBoolPref()` | 临时内容偏好持久化（storage 异常安全） |
| `FoldSection` | 分区折叠标题（箭头、数量、可选右侧操作、`aria-expanded`） |
| `renderSessionGroups()` | 分区内按工作区分组 + 7 条截断 |

## 6. 验收步骤（需重启宿主加载新 client）

1. 重启母体（或让宿主重新加载 `@local/dsh-fang` client 半）；
2. 打开瓮城面板，左栏应出现「进行中 / 已归档 / 临时」三组标题；
3. 造 8 个以上进行中会话 → 只显示 7 条，出现「展开剩余 N 个」，点击后全部显示；
4. 点「已归档」「临时」标题 → 默认收起，点击展开；
5. 点「隐藏临时内容」→ 临时分区消失，刷新/重开面板后仍隐藏；
6. 右栏同理：进行中任务默认展开、已归档默认折叠、快速派生任务进「临时」默认折叠；
7. 隐藏临时内容后若只剩临时项 → 显示空态 + 一键恢复按钮。

## 7. 已知限制

- 视觉验收需要重启宿主（本次改动未触碰运行中的后台宿主进程）；
- 「临时」的判定基于任务标题字符串；如果未来派生流程支持用户命名，需要在 `QUICK_DERIVE_TITLE_RE`
  或任务数据里补一个显式标记（那时应走协议新增字段，而不是继续猜标题）；
- 归档/临时分区不做「加载更多」：它们来自同一份已加载列表，先折叠不额外请求。
