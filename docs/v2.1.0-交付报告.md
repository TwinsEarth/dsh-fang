## 2. 平台事实与取舍（实测，不是推测）

1. **图标可行**：`sidebar.panellist` 的登记项组件就是图标渲染器（`renderSlot('sidebar.panellist', {size, active}, {only:id})`），
   所以「红色城门」是一个 React SVG 组件，而不是 label 文本。
2. **单击归外壳**：`PanelRow` 的 `onClick → selectPanel(id)` 由宿主拥有，插件不能接管单击；
   单击进面板因此是"免费"的——只要 `main.key='fang'` 与 `sidebar.panellist.id='fang'` 同时存在。
3. **双击只能在图标这一层挂**：事件从图标冒泡到行按钮不冲突，所以双击热区 = 18px 图标本身；
   dock 徽标（插件自有 DOM）是更大的双击目标，`title` 里写明两个手势解决了可发现性。
4. **颜色**：全部走 `--dsw-alias-*` + 回退；红色是插件艺术色 `--fang-gate-accent`（默认 `#C62828`），
   不借用宿主的 danger 语义色。
5. **弹窗拦截**：`window.open` 在 5–20s 异步之后调用会脱离手势上下文 → 被拦时面板内的
   「打开分身 ↗」是兜底，不预开 `about:blank`。

## 3. 新增/变更清单

### Client 半（`client.js`）
- `GateGlyph`：红门图标 + 双击快速派生（仅装饰，`aria-hidden`，可读名由行 label 提供）。
- `FangPanel`（`main.key='fang'`）：门楣（角色/就绪比/主按钮）→ 会话列表 → 任务列表 →
  选中确认条（两段式）→ 最近派生结果卡（含打开链接）→ 页脚提示 + 独立门户 ↗。
  状态：加载骨架/空态/离线常驻条 + 重试；5s 轮询。
- `FangBadge`（dock）：状态点 + 单击开面板 + 双击快速派生。
- 单模块级共享 store：一次派生结果同时通知面板与徽标；单飞 + 冷却防止重复派生。

### Host 半
- 新插件 `fang-session-catalog`（mother-only）：`status/listSessions/getSession/readHead/digest`；
  路由 `GET /fang/api/sessions`、`/sessions/item`、`/sessions/head`；只读，不接受路径，只收不透明 `sessionId`。
- `src/lib/session-format.mjs`：workspace 索引解析、目录扫描（只 stat）、多帧 zstd 有界头读（只解第一帧）、
  `redact()`、`digest()` ≤32KiB（超限 halt）。
- `orchestrator`：`createTask({seed})` 在 provision 后、spawn 前写 `<forkHome>/fang-seeds/<seedId>.md`；
  `derive({sessionId?, title?})` = catalog.digest → seed → createTask；`POST /fang/api/derive`；
  `taskView.seed` 暴露来源/大小；`normalizeSeed` 64KiB 上限。
- kernel：`SERVICE.sessionCatalog`、`ROW.sessionCatalog`、`MATRIX.sessionCatalog=['mother']`、
  `resolveSessionsLayout()`、`FANG_VERSION=2.1.0`；package exports `./session-catalog`；patch 新增一行。

## 6. 已知边界 / 待你操作

1. **生效状态：已生效**（2026-11-01 宿主重启后活体实测）——
   `sidebar.panellist` occupant `{id:'fang', order:90, active:true}`、`main` key `fang` 注册 active、
   `conversation.composer.dock` 的 `fang-badge` active、宿主行 `include:fang-session-catalog` 已加载。
   即「瓮城」导航项、控制面板与输入框徽标都在运行中的页面里。
2. **双击热区**：导航行点击归外壳，双击只能挂在 18px 图标上（不是整行）；dock 徽标是更大的双击目标。
3. **会话继续 = lineage + 有界摘要**：不复制 transcript、不挂载母体会话目录（母体不可变）；
   摘要上限 32KiB，超限 fail-closed。真实"把会话搬进分身"仍是 NOT ESTABLISHED（未文档化格式）。
4. **头读只解第一帧**：zstd 多帧日志的预览只覆盖第一帧（如实标 `first-frame-only`），跨帧历史未验证。
5. 会话标题在无原生标题来源时用占位（短 id/workspace 标题），不假装有标题。
6. 商用功能仍只有钩子（v2.0 边界不变）。
