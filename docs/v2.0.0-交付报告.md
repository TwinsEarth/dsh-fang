## 3. 关键设计落地

### 3.1 部署矩阵（同一 bundle 双角色）
`DSH_FANG_ROLE`（forker 注入）> config.role > mother；未部署角色**不注册服务/定时器/路由**。
e2e 在真实分身的 `/fang/adapter/status` 里验证：
`scorer/router/healer/approver/hotReloader/buffer/auditor/adapter = true`，`orchestrator/forker = false`。

### 3.2 跨进程协议（不共享 ctx）
母体 → 分身 HTTP：`hello / status / approvals / audit / command`，命令
`ping/status/flush-buffer/score-plugin/read-plugin/route-confirm/approvals/approval-decide/archive`；
鉴权复用分身 token；remote 客户端统一 `{ok,kind,error}`，永不抛（超时 AbortController）。
文档：[PROTOCOL-V2.md](PROTOCOL-V2.md)。

### 3.3 任务生命周期
`createTask → Forker(端口池+干净模板) → spawn(DSH_HOME 独立, role=fork) → URL 解析 → Adapter 握手 → READY`；
`archiveTask = 分身 archive(flush+审计) → Forker.reap(进程树+安全删 home)`。
`promoteTask = read-plugin → fork 评分 → 母体阈值复核 → Router 初判 → Approver(promotion, red) → A/B → staging`。

### 3.4 Router 时序
`decide`（母体，quickScan，派生之前）+ `confirm`（分身，只升不降；deny 原样返回）。
rank：`sandbox < container < deny`。

### 3.5 评分分叉
`thresholds.mother = 20/40/60/80`（= v1）、`thresholds.fork = 25/45/65/85`；
每个 Assessment 带 `basis{environment,thresholds,note}`，报告里显式标注「本评分基于 <env> 阈值」。

### 3.6 容器兜底（本机实测）
- `FANG_CONTAINER_LIVE=1 node --test test/container-host.test.mjs` → 9/9；
- 真 AppContainer 执行成功；容器代码上报 3 个 write 帧 → 宿主按申报清单落盘
  `plug/live.txt`；`other/evil.txt` → `not-declared`、`../escape.txt` → `dotdot-segment`，越界文件未产生；
- 默认测试只覆盖降级路径（无 PowerShell/非 Windows → unavailable），CI 不依赖容器。

### 3.7 v1 兼容
`fork/reap/listForks/promote` 保留为别名；v1 的 `/fang/api/forks*`、`/api/reap`、`/api/promote` 路由保留；
注册表升级为 `tasks.json`（首次读取 v1 `forks.json` 迁移，不再与 forker 的 `forks.json` 双写）。

## 6. 本轮发现并处理的问题

1. **profile 身份歧义**：`detectProfileTag` 先看 argv 会误取模板名（`web`），导致 e2e 母体找不到分身模板。
   已改为 `DSH_PROFILE` 优先；orchestrator 的模板默认值改用 `DSH_PROFILE_DIR`（启动器给出）。
2. **registry 双写风险**（T7 发现）：forker 与 orchestrator 都写 `<dataDir>/forks.json`。
   已拆为 `tasks.json`（orchestrator v2，含 v1 迁移读取），forker 继续拥有 `forks.json`。
3. **插件删除网络故障**：`remove_bundle` 因 pnpm supply-chain 策略（registry 超时 + `@michengai/dsh-agency-agents@1.2.21` 发布未满 24h）失败，
   但已把 `@local/dsh-fang` 从 `dsh.profile.bundles` 移除。**已修复**：从备份恢复并写回 bundle 层，
   依赖与 junction 保持完好（`link:E:/GPT/dsh-fang`，包版本 2.0.0）。
4. 历史测试与角色矩阵冲突：fork-only 插件的旧测试已固定 `DSH_FANG_ROLE=fork`（Lead 统一收口）。
