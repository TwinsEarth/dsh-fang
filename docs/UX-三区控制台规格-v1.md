# 瓮城控制台 · 三区 UX 规格 v1

- 评审对象：`client.js`（面板 client half），基线 `3.0.4`
- 规则依据：母体 / 原身 / 分身三层；`src/lib/permissions.mjs` 的环境能力契约；`src/lib/essence.mjs` 的官方原身、两级子原身、VIP 配额；`docs/ESSENCE.md`
- 关联评审：`docs/REVIEW-三区隔离与快照回流.md`（系统契约与 P0 前提，本文不重复论证，只引用结论）
- 交付对象：前端实现 + 交互验收
- 修订：v1.1 补齐需求编号（1.1–2.2）与按钮矩阵、权限驱动渲染矩阵、旧任务面板迁移、带 ID 的验收项；把"备份/升级百分比"改为无服务端进度事件的不定态（原 v1 该两处不可实现）

## 0. 结论

**方向成立，但现状不是"三区"，而是"两栏实体视图 + 设置卡片"。**

- 左栏是**母体会话**，不是原身；原身层在 UI 里完全不存在（client 侧没有任何 essence 数据消费）。
- 右栏是**分身任务卡**，但卡里展开的是分身会话目录，把本应属于分身 Web 的内容复制到了母体面板。
- 母体信息被拆成三处：顶栏"镜像"按钮、镜像卡内部、页脚版本号；备份时间与升级入口都不是"常显"。
- 三层规则中的"动作面互斥"只实现了一半：分身卡没有插件入口（对），但原身卡的动作面干脆没有（缺）。

**三条不变量（建议写进组件契约与代码评审清单）**

| # | 不变量 | UI 含义 |
|---|---|---|
| I1 | 动作面互斥 | 母体栏只做版本/备份/更新；原身卡只做配置与派生；分身卡只做运行时（打开/归档/下载/删除）。跨层动作不抄近路。 |
| I2 | 数据面分层 | 配置可导出；会话/日志只归档或导出，不"回流"；三种"归档"必须三种名字。 |
| I3 | 状态单向 | 服务端权威；UI 只派生视图。派生 ghost、归档中、停止中都是可被权威状态覆盖的临时态，超时即撤下。 |

**UI 侧 P0 不是换皮，而是四件事**：把三层画出来、把母体状态常显、把分身运行时说全、把阻塞前置。

### 0.1 逐条对照用户三层规则

| 用户规则 | 现状 | 判定 |
|---|---|---|
| 顶部母体栏：版本/备份时间/检查更新/立即备份/从备份还原；母体不可删除；仅母体可升级 | 版本在页脚；备份/还原/升级在"镜像"卡内；删除本就不存在，但"不可删除/唯一可升级"没有任何 UI 声明 | **部分成立**：能力对，位置错，规则不可见 |
| 左侧原身卡：官方推荐/自建/子原身；插件数与 VIP 额度；新建/新建子原身/派生/设置/复制/归档/删除/下载 | 原身层 UI 为 0；左栏是母体会话；派生挂在母体顶栏且不问来源 | **不成立**：需新建整个区 |
| 右侧分身卡：运行时长/端口/PID/状态灯；打开/归档/下载/删除；不显示装插件入口 | 端口/状态有；PID 只在诊断；无时长（后端缺 startedAt）；只有打开/归档；无插件入口（对） | **部分成立**：信息与动作都缺一半 |
| 分身 Web：会话 1:1 + 分支切换器 | 母体面板重复展开分身会话；无分支；分身 Web 只有说明卡 | **冲突**：会话双源，分支缺失 |

> 四条规则里，只有"分身不装插件"在面板层成立（卡片无入口、环境能力也拒绝）；其余三条要么位置错，要么缺失。

### 0.2 需求编号（1.1–2.2）与落点

两条命名裁决（不先对齐，实现必走偏）：

- 原身的"归档"在本 spec 中叫 **"停用"**（可再启用）；"归档"只留给分身（停进程、留 home）；母体对应的词是 **"备份 / 恢复点"**。三个词三个意思，见 §2.7。

## 2. 三层权限模型

### 2.1 三个判断轴

权限不是一张表，而是三层依次判断：

1. **面（surface）能力**：这个界面所在的环境根本允许做什么（`permissions.mjs` 已定义）。
2. **对象（object）状态**：这个原身/分身的锁定、冲突、父子、配额。
3. **角色（role）**：当前账户能不能做。单机默认 `owner`；企业/远程接入后启用 `admin/member/viewer`。

### 2.2 环境能力（平台不变量）

| 能力 | 母体 mirror | 原身 essence | 分身 derived |
|---|---|---|---|
| 升级/回退母体 | ✅ 唯一 | ❌ | ❌ |
| 备份/还原母体 | ✅ | ❌ | ❌ |
| 安装/修改第三方插件 | ❌（仅官方内置，不可增删） | ✅ | ❌ |
| 打开/继续会话、分支 | ❌ | ❌ | ✅ |
| 新建原身 / 子原身 | 由母体面板代理 | ❌（回母体面板） | ❌ |
| 派生分身 | 由母体面板代理 | ❌（回母体面板） | ❌ |
| 归档/删除分身 | 由母体面板代理 | ❌ | ❌ |

> 结论：**分身卡与分身 Web 永远不出现"装插件"入口；原身卡永远不出现"打开会话"；母体永远不出现"删除母体"。** 这不是"隐藏"，是能力不存在。

### 2.3 对象状态规则

| 对象 | 状态 | 结果 | 呈现 |
|---|---|---|---|
| 原身 | `official` / `locked` | 设置、停用、删除、改 tier 全部不渲染 | 卡片显示 🔒「官方 · 锁定」，副文案"官方推荐原身不可修改" |
| 原身 | `parentId !== null`（子原身） | "新建子原身"不渲染 | 类型标「子原身 · 父：X」 |
| 原身 | 有子原身 | "删除"禁用 | 原因："先删除 2 个子原身" |
| 原身 | `conflicted` | "派生"禁用，主提示改为"解决冲突" | 3px 琥珀边 + "2 个配置冲突" |
| 原身 | `stale` | "派生"禁用，提示"待重算" | 灰灯 + "重算" |
| 分身 | `starting/stopping` | 打开、归档、下载、删除全禁用 | 灯 + "启动中 / 停止中"，操作条整体降级 |
| 分身 | 运行中 | 删除禁用 | 原因："先归档，再删除存档" |
| 分身 | 已归档 | 打开禁用；还原/下载/删除可用 | 归档行 |

### 2.5 隐藏 / 禁用 / 只读：决策顺序

按顺序取第一个命中的规则：

1. **能力不存在** → 不渲染（含 DOM，不是 `display:none` 敷衍）。
2. **角色完全无权限** → 不渲染；若该动作是页面主路径（派生、打开），改为禁用 + "无权限 · 申请"。
3. **对象锁定/官方** → 不渲染（锁定意味着永远不能做，禁用是虚假希望）。
4. **对象状态/配额阻塞** → 渲染但禁用 + **可见原因** + 出口。
5. **进行中（busy）** → 渲染但禁用 + "处理中…"，不改变布局。

配套规则：

- R1 隐藏不得造成布局跳变：动作区固定高度，溢出菜单按钮位置固定。
- R2 禁用必须有**就地文案**，不能只靠 tooltip（触屏与读屏都拿不到）。
- R3 平台不变量用"说明"表达一次（母体栏标题的"唯一"标 + tooltip），不用禁用按钮暗示。
- R4 子原身能力 ⊆ 父原身；父级没有的能力，子级 UI 不出现。
- R5 危险动作统一进溢出菜单，且与普通项用分隔线隔开。
- R6 403 与 404 必须分开：403 = "当前角色无权限"（+ 申请）；404 = "功能未上线/宿主版本旧"（+ 重启/升级），绝不互相冒充。

| 原身 | E-02 | 原身 `stale` | 禁用 | `配置待重算` ｜ 重算 |
| 原身 | E-02 | 车间 `running+starting+stopping ≥ maxForks` | 禁用 | `车间已满 8/8` ｜ 归档一个分身 / 扩容（仅 `capacity.source=plan`） |
| 原身 | E-02 | 本卡派生中 | 禁用 | `派生中… 已用 7s` ｜ — |
| 原身 | E-03…E-08 | 无路由（SV6 / SV9 未上线） | 隐藏 | — ｜ —（不渲染死按钮） |
| 原身 | E-04 | `parentId !== null`（子原身） | 隐藏 | — ｜ — |
| 原身 | E-07/E-08 | `official && locked` | 隐藏 | — ｜ — |
| 原身 | E-08 | 有子原身 | 禁用 | `先删除 2 个子原身` ｜ 查看子原身 |
| 原身 | E-08 | 角色低于 owner | 禁用 | `当前角色无删除原身权限` ｜ 申请权限 |
| 分身 | C-01 | starting / stopping | 禁用 | `启动完成后可打开` ｜ — |
| 分身 | C-01 | 无 URL（failed / archived） | 禁用 | `该分身没有可打开的地址` ｜ 还原（归档行） |
| 分身 | C-02 | 无 URL | 禁用 | `没有可复制的地址` ｜ — |
| 分身 | C-03 | starting / stopping | 禁用 | `正在启动 / 正在停止` ｜ — |
| 分身 | C-03 | archived | 隐藏 | — ｜ —（归档行才出现"还原"） |
| 分身 | C-04 | 车间已满 | 禁用 | `车间已满 8/8` ｜ 归档一个运行中的分身 |
| 分身 | C-05 | 无导出路由（SV9） | 隐藏 | — ｜ — |
| 分身 | C-06 | 运行中 / 未归档 | 隐藏 | — ｜ —（只对归档项渲染） |
| 分身 | C-06 | 未勾选确认 | 禁用 | `勾选"我已知晓会永久删除 home"` ｜ — |
| 全局 | 全部 | 任一长操作进行中（单飞） | 其余禁用 | `另一项操作进行中` ｜ — |
| 全局 | 全部 | 403 | 就地提示 | `当前角色无此权限：{动作}` ｜ 申请权限 |
| 全局 | 全部 | 404 路由缺失 | 就地提示 | `宿主未提供该接口（vX 起）` ｜ 重启后重试 |
| 全局 | 整页 | 环境类型无法识别 | 只读条 | `环境类型无法识别，已按只读处理` ｜ 诊断 / 重新探测 |

配套规则：

- 能力缺失一律"隐藏"而不是"禁用"：禁用暗示"以后能用"，隐藏表示"这一层不提供"（§2.5 第 1、3 条）。当前有 7 个原身动作属于此类（新建、设置、＋子原身、复制、下载、停用、删除），先隐藏，等 SV6 上线同版本再一起放出。
- 每条禁用都要 `aria-describedby` 指向可见原因节点；不靠 tooltip，触屏与读屏都拿不到。
- 同一张卡同时命中多条时按 §2.5 顺序取第一条；"单飞"永远最后判。
- 403 与 404 文案不得互换：404 写成"没有权限"会把宿主版本问题变成账号问题。

### 2.6.1 权限常量 → 按钮的映射（防误用）

`permissions.mjs` 的两个能力组只描述**目标宿主**，不描述面板宿主。混淆这两者会得到两个错误结论："母体里不能打开分身"和"原身里可以装插件但三区里找不到入口"。

| 能力组 | 作用宿主 | 受影响的按钮 | 正确用法 | 错误用法 |
|---|---|---|---|---|
| `installPlugins` | essence | **无** | 三区里不出现任何插件按钮；出现即越层 | 在原身卡上放"装插件"（分身/母体都会误显示） |
| `openSessions` | derived | C-01、W-02、W-03 | 只在目标宿主内判定；母体面板打开的是分身的 URL，按 derived 判 | 用母体的 `openSessions=false` 去禁用 C-01 —— 那会把"打开分身"误杀 |

结论：三区里只有"分支入口"会真正消费能力常量（且当前被 SV8 缺失整块隐藏）；其余按钮的可见性由对象状态与角色驱动（§2.6），不要拿环境能力当第二套开关。

### 2.7 两个易错文案

- 现状顶栏"母体 只读"→ 改为 **"母体 · 唯一"**；"只读"移到派生对话框的会话选择器头部（"会话只读，仅选择与派生"），不要再挂在母体身份上。
- 原身的"归档"与分身的"归档"同名不同义 → 原身一律叫 **"停用"**（可启用），分身才叫"归档"；母体叫"备份 / 恢复点"。三词三义。

### 3.4 实现约束（与现有 client half 对齐）

现有面板用**内联 style + `useMediaQuery`**，没有 CSS 文件；因此断点不是媒体查询字符串，而是 hook 返回的三个布尔量，必须一次收敛：

| 断点 | 条件 | 形态 |
|---|---|---|
| compact | < 768 | 母体栏 64 + ⋯；原身手风琴；分身 1 列 |
| medium | 768–1279 | 母体栏：768–1023 折两行 88，1024–1279 单行 56；原身：<1024 横向卡带，≥1024 280 竖列；分身 2 列 |
| wide | ≥ 1280 | 320px + 自适应；分身 2–4 列 |

- **废弃现在的单一 `isNarrow(≤980)`**：一个布尔量撑不起三档，且 980 正好落在"原身区 280 + 分身两列"最挤的区间。
- 母体栏折行用 `flex-wrap` + `min-width: 0`，不用绝对定位；否则 200% 缩放会重叠。
- 原身列宽用断点常量（280/320/336/360），不要让 `grid-template-columns` 的 auto 行为决定，否则 1024 会被分身网格挤压。
- 分身网格 `repeat(auto-fill, minmax(300px, 1fr))` 在 < 1024 改为显式 1–2 列，避免 Safari 的 auto-fill 抖动。
- 移动端 DOM 顺序必须是 母体 → 原身 → 分身（Tab 顺序 = 视觉顺序），**不允许用 `order` 改视觉顺序**。
- 三区各自滚动，`overscroll-behavior: contain`；区头 sticky 的 `z-index` 必须低于母体栏（20），否则滚动时区头压住母体栏。

### 3.5 信息层级与字阶

| 层级 | 内容 | 字阶 |
|---|---|---|
| L0 | 母体身份 + 版本 | 15/600；版本 11 mono |
| L1 | 区标题 + 计数 + 容量 | 13/600；计数 11.5 |
| L2 | 对象名 + 状态 | 14.5/600；状态 11.5/500 |
| L3 | 指标（插件/配额/端口/PID/时长） | 11.5/400；数字 mono + tabular |
| L4 | 动作 | 12/500 |
| L5 | 诊断、错误码 | 10.5 mono（仅此层允许 10.5） |

字阶：18 / 13 / 14.5 / 12.5 / 11.5 / 10.5（mono）。行高：24 / 18 / 20 / 19 / 17 / 15。中文字距 0；只有状态标签全大写英文时才用 0.04em，本项目基本不用。

### 3.6 视觉"物理感"

- 区与区之间：1px 边 + 16px 间距，**不叠阴影**；卡片只有 1px 边，无投影。
- 原身区底色比分身区低一档（`rgba(127,127,127,.02)` vs `.035`）：配置层更"平"，运行时层更"凸"。
- 主色只给主操作与选中；状态色只给状态；元数据一律次级文字色。
- 焦点环 2px 主色 + 2px offset；深色主题用宿主亮色 token，保证 3:1。

## 4. 母体栏

### 4.1 结构

| 区块 | 内容 | 交互 |
|---|---|---|
| 左：身份 | 门形图标 24 + "母体" 15/600 + `[唯一]` 10.5 Tag + `v3.0.4` mono 11 | 点版本复制；tooltip："母体是唯一层，不可删除；升级只在这里发生" |
| 中：新鲜度 | 备份状态 + 更新状态，两项用 1px 分隔 | 点备份 → 恢复点抽屉；点更新 → 更新详情弹层 |
| 右：动作 | 检查更新 / 立即备份 / 从备份还原（32px）；`⋯` 收纳：母体连接、独立门户、诊断 | 见 4.2 状态机 |

**不渲染**：删除、卸载、停用、重命名母体。母体页面上任何位置都不出现这些词（含菜单、空态、错误文案）。

### 4.2 状态机

**备份**（来自 `meta.lastBackupAt / nextBackupAt / interval`）

| 状态 | 视觉 | 文案 | 动作 |
|---|---|---|---|
| 从未备份 | 琥珀点 | `从未备份` | 立即备份（主） |
| 正常 | 绿点 | `备份 2 小时前`（title 绝对时间） | 立即备份 |
| 到期 | 灰点 | `备份 26 小时前 · 已到期` | 立即备份 |
| 超期 | 琥珀点 | `备份 3 天前 · 建议立即备份` | 立即备份（主） |
| 进行中 | 转圈 | `备份中… 已用 12s` | 禁用其它母体动作 |
| 失败 | 红点 | `上次备份失败：磁盘空间不足` | 重试 / 清理旧备份 |

**更新**

| 状态 | 视觉 | 文案 | 动作 |
|---|---|---|---|
| 检查中 | spinner | `检查中…` | 禁用 |
| 已是最新 | 绿点 | `已是最新 v3.0.4` | 无 |
| 可升级 | 主色点 | `可升级 v3.0.5` | 按钮变 `升级` |
| 未配置源 | 灰点 | `未配置更新源` | `去设置`（不得显示"已是最新"） |
| 离线/失败 | 琥珀点 | `检查失败（离线）` | 重试 |
| 升级中 | 转圈 | `升级中… 已用 12s · 请勿关闭 DSH` | 全栏只读 |
| 升级失败 | 红点 | `升级失败，已回滚到 v3.0.4` | 诊断 / 重试 |

> **进度口径（P0 必须接受）**：`POST /mirror/backup`、`/mirror/restore`、`/mirror/upgrade` 都是同步长请求，服务端不返回阶段、也不返回百分比。UI 只能给"已用 Ns + 不定态进度轨"，不许画 42%，也不许写"装配 2/4"——那是编出来的事实。要真实阶段，需 SV10（任务化返回 phase + 轮询/SSE）。

**还原**：抽屉 420px，列表项 56px（时间、版本、体积、恢复点/滚动），选中 → 底部"还原到此时点"；固定勾选"还原前自动备份当前镜像"（不可取消）。还原中栏内进度；失败保留抽屉并明写"当前镜像未改动"。

### 4.3 强制规则

- 升级入口**只**存在于母体栏；原身/分身侧最多出现"需要母体重算"的文字链，不能出现"升级"按钮。
- 母体栏任何动作失败都**不清空**面板数据，只降级为顶部条 + 上次成功时间。
- `Ctrl/Cmd+R` 不劫持；刷新仍在 ⋯ 菜单，避免和浏览器冲突。

## 5. 原身卡

### 5.1 类型

| 类型 | 标识 | 视觉 | 动作差异 |
|---|---|---|---|
| 官方推荐 | `official && locked` | 主色 Tag + 🔒；左条绿 | 设置/停用/删除**不渲染** |
| 自建（顶层） | `parentId === null` | 中性 Tag「自建」 | 全部动作（按角色/配额） |
| 子原身 | `parentId !== null` | 信息色 Tag「子原身 · 父：X」 | 新建子原身**不渲染**（两级限制） |

### 5.2 信息

三行，指标控制在 5 个以内（插件 / 分身数 / 套餐 + 2 条配额），避免数字墙：

1. 状态灯 + 名称（14.5/600，单行省略）+ 类型 Tag + 溢出按钮。
2. `插件 14` · `分身 3` · `VIP10`（VIP 等级是账户级，不是原身 meta 的 `tier`，见 5.6）。
3. 配额迷你条：顶层 `子原身 1/10`、所有 `会话 6/10`（分母来自 plan.quotas）；≥80% 转琥珀，100% 转红并加"已达上限"。

行尾 meta（可选）：`更新于 10-28` / `冲突 2` / `待重算`。

### 5.3 动作分层

| 位置 | 动作 | 条件 |
|---|---|---|
| 主操作 | 派生 | 原身 `ready`、配额内、有权限 |
| 次操作 | 设置、＋子原身（仅顶层） | API 未上线时**整项不渲染**（能力不存在，§2.6）；不接受"禁用 + 接口未上线"的假按钮——路线图写在文档里，不写在按钮上 |
| 溢出 | 复制、下载、停用、删除 | 停用/删除在分隔线后；删除为 danger |

8 个动作不并排：主 1、次 2、溢出 4。溢出菜单宽 200，项高 36，危险项用 danger 文字色 + 分隔线。

### 5.4 选中与联动

- 点卡片任意空白 = 选中；选中态为 2px 主色内描边 + 4% 主色底；`aria-current="true"`。
- 右区标题变为 `分身 · 来自「X」`；切换原身时右区滚动位置回到顶部，焦点移到右区 `h2`（`tabindex="-1"`）。
- 记住上次选中（localStorage），失效则回落到官方推荐 → 第一个可用原身。
- 键盘：↑/↓ 在卡间移动（roving tabindex），Home/End 首尾，Enter 选中，→ 进入右区第一张卡。

### 5.5 空 / 载入 / 错误

| 场景 | 呈现 |
|---|---|
| 首次无原身（官方 seed 失败） | 虚线卡："还没有原身" / "母体只读；原身用来装插件、改设置。" / [查看母体诊断]（SV6 前不渲染"新建原身"，见 §9） |
| 加载中 | 2 张骨架卡（124 高），不显示 0 计数 |
| 读取失败 | 区内 Callout："原身列表不可读" + 错误码 + 重试 + 诊断；保留上次数据并标注时间 |
| 全部停用 | 空态 + "已停用 n 个" 入口 |

### 5.6 数据缺口（必须先补）

- `pluginCount`：`essence/list` 只返回 meta，没有插件数；不可前端猜。
- 账户级 `plan.tier / quotas / usage`：现在只有每个原身的 `tier`（官方硬编码 `vip100`），不能代表用户套餐；**卡片上的 VIP 等级必须来自 `plan`，不是 `essence.tier`**。
- 原身创建/设置/复制/停用/删除/下载：均无 HTTP 路由；UI **整块不渲染**（§2.6），等 SV6/SV9 上线同版本再放出。

## 6. 分身卡

### 6.1 状态：两根轴，两个组件

| 轴 | 组件 | 取值 | 文案 |
|---|---|---|---|
| 运行时 | 8px 灯 + 文本 | starting / running / stopping / failed / crashed / archived | 启动中 / 运行中 / 停止中 / 已停止 / 已崩溃 / 已归档 |
| 适配器 | Pill（小） | handshaked / pending / lost | 适配器就绪 / 未就绪 / 失联 |

- 灯永不单独存在；色盲安全靠文本。
- `ready` 不是运行时状态，禁止再作为灯的一种；它是"适配器就绪"。
- 启动中/停止中：琥珀 + 1.2s 呼吸（reduced-motion 下静态）；崩溃：红 + 一次 1.2s 脉冲，不循环。

### 6.2 指标

| 指标 | 规格 | 缺失时 |
|---|---|---|
| 运行时长 | mono 12；`02:14:33` / `3d 04:12`；title 绝对起止 | 显示 `—` + title "宿主未提供 startedAt" |
| 端口 | mono 12；可点击复制；`18042` | `—` |
| PID | mono 12；中点截断（`214…488`），title 全量；可复制 | `—` |
| 来源原身 | 11.5 次级；链接回左区选中 | 隐藏 |
| URL 主机 | 11.5 mono 省略 | 隐藏 |

运行时长每 1s 更新，但只重渲染 `<time>` 子节点；`document.hidden` 时暂停；读屏不播报秒级变化。

### 6.3 动作与状态矩阵

| 运行时 | 打开 | 复制链接 | 归档 | 下载(P2) | 删除存档 |
|---|---|---|---|---|---|
| starting | ✘ | ✘ | ✘ | ✘ | ✘ |
| running | ✔ | ✔ | ✔（确认） | ✔（某一时刻副本） | ✘（先归档） |
| stopping | ✘ | ✘ | ✘ | ✘ | ✘ |
| failed | ✘ | ✘（多半无 URL） | ✔ | ✔ | ✘（先归档） |
| crashed | ✘ | ✘ | ✔ | ✔ | ✘（先归档） |
| archived | ✘ | ✘ | — | ✔ | ✔（勾选确认） |

- **打开**：主按钮 32；无 URL / starting / stopping 时禁用，原因就地一行："启动完成后可打开"。
- **复制链接**（R2.1 的"复制"）：复制 `task.url` 到剪贴板，成功后 `aria-live` 播报"地址已复制"；无 URL 时禁用。语义是**分享地址**，不是克隆实例——克隆要新 home、新端口，属于服务端 clone（本版不做，见 E-09）。
- **归档**：ghost；确认文案补一句"会话已持久化；未保存的运行态会随进程停止丢失"。
- **溢出**：下载、删除（分隔线 + danger）。**永不出现**：装插件、设置、升级、改端口。
- **会话数**：不做 N+1 轮询。P0 卡片不显示会话数；P1 由 SV11 的 `sessionCount / branchCount` 提供，才显示"3 个会话 · 2 个分支"。
- 归档后卡片移入右区底部"已归档（n）"折叠行，不留在主网格。

### 6.4 卡片结构

```
[灯] 运行中 02:14:33            修复路由守卫               [⋯]
端口 18042 · PID 21488 · 适配器就绪 · 来自 开发者推荐
[打开]                                          [归档]
```

标题单行省略（title 全量）；指标行在 <360 时换行，端口/PID 不拆开；动作条底部右对齐，固定 32 高，避免换行抖动。

## 7. 派生进度与落位

### 7.1 进度来源：同步请求 vs 任务化

现状 `POST /fang/api/derive` 是**同步阻塞**请求（5–20s 一次回包），没有 202、没有 opId、没有 phase。UI 必须区分两种模式，但视觉保持同一张 ghost 卡：

| 模式 | 依据 | 能显示的 | 不能显示的 |
|---|---|---|---|
| 兼容（P0，现状） | 单次 POST，最终 200/4xx | 已用时间；四段**推断**轨（第 4 段在响应到达时直接判就绪） | 服务端阶段名、取消、真实失败点 |
| 任务化（P1，SV7） | 202 + opId + phase 轮询/SSE | 真实阶段、取消、超时归因 | — |

规则：

- 兼容模式下进度轨只表达"还在进行"，`aria-valuetext` 写"已等待 7 秒，通常 5–20 秒"，**不写阶段名**；写了就是编事实。
- 两种模式共用同一张 ghost 卡与同一套落位/对账逻辑（§7.3、§7.5），差异只在数据层，不在视觉层。
- 兼容模式下"取消"按钮不渲染——没有取消接口，渲染出来点了只会更糟。

### 7.2 阶段（总预算 20s）

| # | 阶段 | 触发 | 文案 | 预算 |
|---|---|---|---|---|
| 1 | 受理 | 点击 →（任务化：202 + opId；兼容：请求已发出） | 正在受理… | ≤300ms |
| 2 | 装配 | `provisioning` | 装配 profile… | ≤3s |
| 3 | 启动 | spawn 完成，端口/PID 出现 | 启动进程 · 端口 18043 | ≤5s |
| 4 | 握手 | adapter 轮询 | 等待适配器握手… | ≤10s |
| 5 | 就绪 | `running + handshaked` | 已就绪 | — |

上表是**任务化模式**的文案。兼容模式下 1–4 段是推断，统一显示"已等待 Ns · 通常 5–20s"，不得写"装配 profile"这类服务端没有的阶段名（§7.1）。

超过 20s → `failed · timeout`，释放槽位，保留卡片给"重试 / 诊断"。**未收到 ready 不得变绿、不得自动打开窗口。**

### 7.3 Ghost 卡

- 位置：当前原身分身网格顶部；`min-height: 132px`，与真卡同宽同圆角。
- 结构：顶部 2px 四段进度轨 → 骨架标题 60% → 当前阶段文案 12.5 → 计时 `00:07` + `通常 5–20s` → 右下"取消"（仅当 API 支持）。
- 骨架：3 行灰条（60% / 40% / 72%），`aria-hidden`；文案是唯一权威。
- `aria-busy="true"`；进度轨 `role="progressbar"`，任务化模式给 `aria-valuetext="第 2 步，共 4 步，装配 profile"`，兼容模式给"已等待 7 秒，通常 5–20 秒"；两种都不设 `aria-valuenow`（不定态）。

### 7.4 动画

| 事件 | 动画 | reduced-motion |
|---|---|---|
| 当前段推进 | 1.4s 线性 shimmer（左→右） | 静态高亮，无位移 |
| ghost → 真卡 | 高度 200ms + 交叉淡入 160ms | 120ms 透明度 |
| 首次出现 | 1.2s 主色描边脉冲一次（按 taskId 记已播放） | 无 |
| 失败 | 无动画，原地变失败卡 | 同 |
| 归档中 | 灯呼吸 1.2s | 静态 |

### 7.5 对账

- ghost 键 = `opId`（任务化）/ 本地 `seq`（兼容）；真卡键 = `taskId`；服务端返回 `opId` 后绑定，复用同一 DOM，避免"闪两次"。
- 快照出现该 taskId → 原地转正，焦点移到该卡"打开"。
- 连续 2 个快照周期未见 → 变"未确认"卡："未能确认派生结果，请刷新"，给刷新/关闭；**不自动消失、不假装成功**。
- 失败：保留 code + 人话 + 重试；`quota-exceeded` 走第 8 节，不显示通用"派生失败"。
- 多并发：每个 opId 一张 ghost，最多 `headroom` 张；新卡在上，真卡不因状态变化重排。

## 8. 车间满员 / VIP 超额

### 8.1 两个额度不是一回事

| 额度 | 来源 | 计算 | 超出的出路 |
|---|---|---|---|
| 车间（并发） | `maxForks`（默认 8，可配 1–64） | `running + starting + stopping + reserved` | 归档一个分身；管理员扩容 |
| VIP（原身/子原身/活跃会话） | `VIP_QUOTAS` | `maxEssences / maxSubEssences / maxActiveSessions` | 升级 tier；删除/归档 |

> **当前代码里 VIP 表不含"并发位"**。若 UI 在满员时承诺"升级解锁车间位"，是假承诺。除非服务端把容量与套餐绑定（`capacity.source = 'plan'`），否则满员只给"归档 / 扩容"。
> 规格要求：`status.capacity.source ∈ {config, plan}`；`plan` 时才渲染升级 CTA。

### 8.2 三档阈值

| 用量 | 颜色 | 呈现 |
|---|---|---|
| <80% | 绿/中性 | 只显示 `3/8` |
| 80–99% | 琥珀 | `7/8 · 接近上限` |
| 100% | 红 | `8/8 · 已满`；主 CTA `aria-disabled` |

### 8.3 前置禁用与文案

| 场景 | 按钮 | 就地原因 | 出口 |
|---|---|---|---|
| 车间满员 | 派生 `aria-disabled` | `车间已满 8/8` | `归档一个分身`（滚到最早运行卡并高亮归档） / `扩容`（若有权限） |
| 原身会话额度满 | 从会话派生时 `aria-disabled` | `该原身活跃会话 10/10` | `打开分身归档会话` / `升级 VIP` |
| 原身数量满 | 新建 `aria-disabled` | `原身额度 5/5` | `升级 VIP` / `删除一个原身` |
| 子原身额度满 | ＋子原身 `aria-disabled` | `子原身 5/5` | `升级 VIP` / `删除一个子原身` |
| 原身冲突 | 派生 `aria-disabled` | `2 个配置冲突，先解决` | `解决冲突` |
| 无权限 | 派生 `aria-disabled` | `当前角色无派生权限` | `申请权限` |

按钮策略：用 `aria-disabled="true"` 而不是原生 `disabled`，保留可聚焦；点击不执行动作，而是打开对应出口（满员→升级/归档抽屉）。这样读屏用户也能听到原因，而不是遇到一个不可聚焦的死按钮。

### 8.4 引导抽屉（480px 右侧）

1. 标题按触发：`车间已满` / `额度用尽` / `无法派生`。
2. 现状卡：当前套餐、该项用量 `8/8`、被阻塞的动作（保留用户填的标题/会话，不丢草稿）。
3. 方案区：
   - 满员：`归档一个分身`（列出 2 个最久未用，带"归档"按钮）+（仅 `source=plan`）`扩容`。
   - VIP：`vip10 → vip30` 等 1–2 档，标注增量（`原身 +20 / 子原身 +20 / 会话 +20`）；推荐"刚好覆盖当前用量 +1"的最小档。
4. 主 CTA + 次 CTA；无计费接口时，主 CTA 改为 `复制套餐 ID / 联系管理员`，不伪造支付。
5. 脚注：`升级立即生效；已运行的分身不受影响`。

### 8.5 服务端 409 映射

`quota-exceeded` 不能落到通用"派生失败"。映射为：

- 有 `capacity` 信息 → 打开 8.4 满员抽屉，保留原动作。
- 只有错误码 → 顶部条："车间已满（服务端拒绝）" + 归档/重试；错误码放诊断。
- 升级后回到原位置，恢复 CTA，toast：`额度已更新：车间 4/8`。

## 10. 失败态矩阵

| 失败 | 位置 | 文案 | 主操作 | 次操作 | 禁止 |
|---|---|---|---|---|---|
| 母体状态不可读 | 栏下条 | 母体状态不可读；上次成功 15:40，正在显示缓存 | 重试 | 诊断 | 清空面板 |

| 派生失败 | ghost 原位 | 派生失败 · `code` + 人话 | 重试 | 诊断 | 顶部横幅代替卡片 |
| 配额拒绝 | ghost/抽屉 | 车间已满 8/8 或额度 5/5 | 归档/升级 | 取消 | 通用"请求失败" |

| 原身待重算 | 卡内 | 配置待重算 | 重算 | 诊断 | 显示"就绪" |
| 适配器失联 | 卡内 Callout | 进程在运行，但适配器无响应 | 打开 | 归档 / 诊断 | 自动杀进程 |
| 归档超时 | 卡内 | 停止超时：进程仍在运行 | 再次归档 | 诊断 | 把卡移入归档 |
| 会话目录 404 | 派生对话框 E-11 | 宿主未提供会话接口（v2.2.0+） | 重启后重试 | 改用空白派生 | 当成派生失败 |

## 11. 分身 Web：会话 1:1 + 分支切换器

### 11.1 边界

- 这段 UI **只在分身自己的 Web UI** 出现，不进母体面板。
- 母体面板的分身卡只显示"打开"；会话数要等服务端给计数（SV11 `sessionCount/branchCount`）才显示。**不再展开会话列表**——现在每 5 秒对每个存活分身各发一次 `GET /fang/api/tasks/sessions`，删掉它。
- 1:1 的含义：导入的母体会话原样呈现（消息顺序、标题、时间），不做摘要、不改写；若因体积上限只导入了摘要，头部必须标 `仅摘要导入`，并**禁用分叉**（分叉一段摘要没有意义）。

### 11.2 会话头

```
修复路由守卫   [源自母体 · 11-02 14:12]   [主线 ⌄ 2]   [从此处分叉]
```

- 来源 chip：只读，tooltip 显示母体会话 ID 与导入方式（完整/摘要）。
- 分支 chip：`主线` 或 `分支 2`；带分支数；点击开 popover。
- 主按钮"从此处分叉"：从当前最新消息分叉；消息 hover 仍提供"从此条分叉"图标（P2）。

### 11.3 分支 popover（360px）

- 列表行 44：分支名（可重命名）、`自分支点 12:34`、`3 条消息`、当前项 ✓。
- 行尾 `⋯`：重命名 / 删除（删除需确认"不会删除对话内容，只移除分支视图"）。
- 底部：`从此处分叉`（主）。
- 空：`只有主线` + `在任意消息上分叉，会复制此前的对话作为起点。`
- 键盘：↑/↓、Enter 切换、Esc 关闭、焦点回到 chip。

### 11.4 分叉对话框

- 字段：分支名（默认 `分支 2`，可改，≤40 字）；起点预览（当前消息前 80 字）；说明"原分支不变；新分支从此刻起独立"。
- 成功：切到新分支，焦点进输入框，toast `已创建分支「分支 2」`。
- 失败：`分支创建失败：会话正在写入` + 重试；草稿不丢。
- 权限：viewer 不渲染入口；无分支 API 时**整块隐藏**（不是禁用）。

### 11.5 与母体的关系

- 母体面板永不出现分支切换器；最多在分身卡显示 `3 个会话 · 2 个分支`（只读计数）。
- 若需要从母体"从某会话派生"，仍在母体侧；派生后的分支属于分身自己的会话，不回写母体。

### 11.6 依赖

- 需要会话分支 API（列表/创建/重命名/删除）与分支点消息 ID；当前仓库无此能力。
- 没有 API 就不渲染入口；不做"敬请期待"的死按钮。

## 12. 无障碍

### 12.1 结构与语义

- `header`（母体栏）+ 两个 `section[role=region]`（原身 / 分身），`aria-label` 与可见标题一致。
- `h1` 瓮城；`h2` 原身 / 分身；卡标题 `h3`。
- 卡片 `article`，`aria-label` 包含对象名与状态；操作按钮在 DOM 中先于溢出菜单。
- 状态灯 `aria-hidden`，状态文本在 DOM 中；颜色只是冗余编码。

### 12.2 键盘

| 区域 | 键 | 行为 |
|---|---|---|
| 全局 | Tab | 母体栏 → 原身区 → 分身区 |
| 原身列表 | ↑/↓/Home/End | roving focus |
| 原身列表 | Enter / Space | 选中 |
| 原身列表 | → | 进入分身区第一张卡 |
| 卡片 | Enter | 主操作（派生/打开） |
| 菜单/popover | ↑/↓、Enter、Esc | 导航、选择、关闭并回焦 |
| 抽屉/对话框 | Esc、Tab 循环 | 关闭、焦点陷阱 |

不新增单键快捷键；`Esc` 在无浮层时清除选中。

### 12.3 焦点管理

| 动作后 | 焦点 |
|---|---|
| 派生成功 | 新卡"打开" |
| 派生失败 | 失败卡"重试" |
| 归档/删除 | 下一张卡；无卡则区标题（`tabindex=-1`） |
| 切换原身 | 右区 `h2` |
| 关闭抽屉 | 触发按钮 |
| 升级返回 | 原 CTA（已恢复） |

### 12.4 读屏

- 派生阶段：单一 `aria-live="polite"`，阶段变化播报，最多 2s 一次；不播报秒表。
- 失败：`role="alert"`；成功：`polite` 一次。
- 禁用 CTA：`aria-disabled` + `aria-describedby` 指向原因文本；点击打开出口。
- 复制按钮：完成后 `aria-live` 播报"端口已复制"。
- 运行时长：`<time datetime>`；读屏只读一次，不随秒更新。

### 12.5 对比度（实测）

| 组合 | 比值 | 结论 |
|---|---|---|
| `#C62828` 白底 | 5.62:1 | 通过（正文/按钮） |
| 白字 `#C62828` 底 | 5.62:1 | 通过 |
| `#6b7280` 白底 | 4.83:1 | 通过（≥12px） |
| `#8b949e` 白底 | **3.08:1** | **不通过**；10.5px 元数据必须换 `#6b7280` 或 `#5f6672`（5.78:1） |
| `#C62828` 深底 `#1f2328` | **2.81:1** | 不通过；深色主题用宿主亮色 error token |
| `#8a4b08` 深底 | **3.09:1** | 不通过；同上 |
| `#6b7280` 深底 | 3.27:1 | 不通过；深色用宿主次级文字 token |

修复原则：**状态/正文只用语义 token，不用硬编码 fallback 当文字色**；三级文字最小 11px 且 ≥4.5:1；状态点 8px 需 3:1，加深色 1px 内描边。

### 12.6 触控与缩放

- 触屏命中区 ≥44×44（视觉可 32，用 padding 扩大）；桌面 ≥32；相邻目标间距 ≥8。
- 200% 缩放 + 1280 宽：不出现横向滚动；卡片单列；母体栏折行；文字不截断到不可读（省略号必须有 title/aria）。
- 不用 hover 承载唯一信息。

### 12.7 动效

- 只做 120/180/240ms 三档；不自动播放循环动画超过 5s；启动灯呼吸 1.2s 可接受。
- `prefers-reduced-motion: reduce`：shimmer→静态、高度 morph→透明度、脉冲→无。
- 不使用闪烁 >3 次/秒；升级/备份进度用文本 + 进度轨，不靠动画表达。

### 12.8 文案

- 错误不写"出错了"；写"什么失败 + 为什么 + 现在能做什么"。
- 不用颜色词（"点击红色按钮"）；用对象名（"归档「修复路由守卫」"）。
- 破坏性按钮动词与结果一致：删除就是删除，停用就是停用。

## 14. 与旧任务面板的迁移

> 旧面板 = 当前 `client.js` 的"3:7 双栏 + 顶栏工具栏 + 镜像卡 + 读档整页"。迁移不是"加三个区、旧东西留着"，而是**一动作一落点**：旧面板每个可点元素，要么有新落点，要么明确删除并写清替代路径。

### 14.1 迁移原则

1. **入口不丢**：旧面板能完成的每件事，新 UI 必须能完成；做不到就先别删。
2. **一动作一落点**：不允许同一件事两个入口。现在"派生"在顶栏 CTA 和双击图标两处、"归档"在卡片和读档页两处，都要收敛。
3. **术语一次替换**：读档 → 归档行；镜像 → 母体栏；母体打开 → 独立门户；派生新分身 → 原身卡派生。
4. **旧面板保留一版**：开关关闭时完全回退旧面板；两者共享同一份服务端数据，**只迁移视图，不迁移数据**。
5. **不复制内存状态**：新面板从服务端重算视图，只接续筛选态这类纯偏好（折叠态旧面板本来就不落盘，见 §14.4）。

### 14.3 交互原语替换

| 旧做法 | 新做法 | 原因 |
|---|---|---|
| 三处 `window.confirm`（还原 / 升级 / 归档） | 面板内对话框 S3（`alertdialog` + 焦点陷阱） | 桌面壳里 confirm 样式不可控、读屏差、放不下二次信息 |
| 派生成功自动 `window.open` | 不开窗；toast + 卡上"打开" | 抢焦点；并发派生会连开多窗 |
| 顶部 notice 承载所有结果 | 分区就地 + 跨区动作用 toast | 结果必须贴住对象（§7.5） |
| 5s 全量刷新（status + tasks + sessions + 每卡 sessions） | 5s 只刷 status + tasks；`essence/list` 30s；会话计数由服务端 | N+1 与两处状态漂移 |
| 单一 `isNarrow(≤980)` | compact / medium / wide 三档（§3.4） | 一个布尔量撑不起三档布局 |
| 派生期间只显示"已等待 Ns" | ghost 卡 + 四段推断轨 + 落位（§7.1） | 等待期没有对象锚点 |

### 14.4 偏好与本地状态

| 项 | 旧 | 新 | 处理 |
|---|---|---|---|
| 临时内容开关 | `fang.panel.showTemporary`（`'1'/'0'`） | `fang.panel.v3.filter`（`all/abnormal/archived/temp`） | 首次启动读旧键一次：`'1'`→`all`、`'0'`→`abnormal`；写新键后不再读旧键 |
| 折叠态（三分区） | 组件内存 | 同左 + `fang.panel.v3.collapsed` | 不迁移（内存态本来就不跨刷新） |
| 选中原身 | 无 | `fang.panel.v3.essence` | 新键；失效回落：官方推荐 → 第一个 ready |
| 派生 notice | 组件内存 | 不保留 | 改为 ghost 卡，刷新即失（可接受） |
| 镜像偏好 `activeIdleTimeoutMs` | 服务端 preferences | 不变 | 不属于视图，不迁 |

**不迁移的东西**：读档页的滚动位置、开启的卡片、顶部 notice、`busy` 标签。这些没有保留价值，硬迁只会让新面板继承旧缺陷。

### 14.5 灰度与回滚

- 开关：`localStorage['fang.panel.v3.enabled']`（默认 `false`）。**不放服务端 preferences**：P0 要的是"改一个键就回滚"，而服务端加字段得发版；`PREFERENCES_SCHEMA` 支持 boolean，将来收编成本很低。关闭时渲染旧面板，旧面板组件保留到 **v3.2**，且不删 import——回滚不该需要回滚代码。
- 灰度顺序：本机一个浏览器 profile 先开一周 → 同事机器 → 默认 `true`（改默认值是发版动作）。每步只看两个数：派生成功率、归档成功率；任一跌破基线 2 个百分点就关开关。
- 回滚：把 `fang.panel.v3.enabled` 改回 `false` 即生效，无需重启；服务端 API 一个都不改，回滚不涉及数据。
- 埋点（最小集）：`panel.mode`（v2/v3）、`derive.start/ok/fail`、`archive.ok/fail`、`button.disabled`（带 `btnId` 与原因码）。`button.disabled` 是验证 §2.6 矩阵是否真的生效的唯一手段。

### 14.6 宿主边界

| 宿主 | 探测依据 | 渲染 |
|---|---|---|
| 母体（mirror） | `GET /fang/api/status` 200 | 完整三区控制台 |
| 分身（derived） | `/fang/adapter/hello` 200/401 | 现有说明页 + 母体连接卡；**不渲染三区** |
| 原身（essence） | 两者都不是 → `unknown` | 只读说明页："原身宿主不管理分身；请回母体面板"；**不渲染三区**，也不要把它标成"故障" |

这一条决定了"三区"只在母体宿主里出现：原身区的"派生/设置"是母体**代理**原身，而不是在原身里跑一个原身面板。

### 14.7 迁移验收（并入 §15.3 的 AC）

迁移单独的判定线，四条全过才算迁完：

1. 旧面板每个可点元素在 §14.2 表里有且只有一行处置；没有"漏网"的按钮。
2. 母体面板 DOM 中不再出现：`读档`、`镜像`作为按钮文案、`派生新分身`、`母体 只读`（出现即未迁完）。
3. `fang.panel.v3.enabled = '0'`（或未设置）时，旧面板行为与 v3.0.4 完全一致（同一份截图比对）。
4. 开关来回切两次，无重复派生、无重复归档请求（网络面板零重复 POST）。

## 16. 假设与待确认

1. **右侧分身区是"选中原身的分身"还是"全部"？** 本 spec 按 master-detail（选中原身→右区过滤），P1 可加"全部"筛选；若产品要全局列表，需增加来源列与分组。
2. **原身"归档"语义**：本 spec 定义为"停用（可启用）"，避免与分身归档同名。若后端只有删除，则 P1 不渲染该项。
3. **下载内容**：原身=配置包（默认排除 credentials）；分身=会话/日志黑匣子（排除 token/ports）。运行中导出需二次确认"某一时刻副本"。
4. **VIP 是否真实计费**：无计费接口时，升级 CTA 降级为"联系管理员/复制套餐 ID"；不得伪造支付流程。
5. **车间容量是否随套餐变化**：当前 `maxForks` 是配置，VIP 表不含并发位。若产品要"升级解锁车间位"，服务端必须返回 `capacity.source='plan'` 并提供对应配额，否则满员只给"归档/扩容"。
6. **分支切换器是否本期交付**：依赖分支 API；无 API 时整块隐藏（不做死按钮）。母体面板的"会话数"也要等 SV11 的计数，不能为了这一行数字保留 N+1 轮询。
7. **分身"复制"的语义**：本 spec 裁决为"复制访问地址"。若产品实际要"克隆一个分身"，那是新 home + 新端口，需 SV9 的 clone 能力，不能复用 `/derive` 假装是复制。
8. **原身/分身宿主里看不到三区**是否可接受：按 §14.6，这两个宿主只给说明页。若产品要求"在原身里派生分身"，等于把 orchestrator 装进原身 profile，属于架构变更，不在本 spec 范围。
9. **新面板开关归谁**：本 spec 放本机 `localStorage['fang.panel.v3.enabled']`（改键即回滚，零服务端依赖）。若要按账号灰度或远程关闭，再迁到服务端 `PREFERENCES_SCHEMA`（已支持 boolean 字段）。
