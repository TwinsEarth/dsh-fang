# dsh-Fang v2.1.1 交付报告 — 会话可辨认 + 分身不再"僵尸"

> 2026-11-01。触发：控制面板里所有会话都显示成工作区名「GPT」，无法区分；
> 同时截图里的任务显示 `adapter http-404`。

---

## 1. 两个根因（都已在真机数据上证伪/证实）

### 1.1 会话标题被工作区名顶替

- `workspace.json` 里只有**工作区**标题（`GPT`），没有会话标题；
- 真实会话标题在会话日志的 `session/title` 事件里（实测：`data.title`，如
  `「https://github.com/TwinsEarth/dsh-window」`），但它**不在第一帧**——
  第一帧只有 `session` 头（实测首帧 = 1 行 header），旧实现只解第一帧，所以永远拿不到标题；
- `session-catalog` 退回 `workspaceTitle`，于是 8 个会话全叫「GPT」。

### 1.2 分身"僵尸"：fork 的 node_modules 指到了没有 Fang 的 profile

- 截图任务的 `adapter http-404` 不是 Adapter 坏了，而是**分身的 `/fang` 路由全不存在**；
- 真机检查：`<forkHome>/profiles/web-base/node_modules` junction 指向
  `%USERPROFILE%\.dsh\profiles\web\node_modules`，而该 profile 没有 `@local/dsh-fang`；
- 根因：`cordis.patch.yml` 里遗留 `motherProfile: web`，orchestrator 拿它去解析分身模板，
  于是派生出一个"没有 Fang 的分身"——能启动、能访问，但所有 `/fang/*` 404。

---

## 2. 修复

### 2.1 会话标题（`session-format.mjs` + `session-catalog.mjs` + `client.js`）

- 新增 `readBoundedEvents()`：**有界多帧读**（≤64 帧 / ≤2MiB 压缩预算 / ≤4000 事件），
  逐帧解压直到拿到事件；超出如实标 `frame-limit` / `compressed-limit`，绝不整文件解压。
- 新增 `extractSessionTitle()`：`session/title` 事件 > 首条 `user/message` 文本（截断 160/80 字符）> null；
  返回 `title / titleSource / preview / messageSeq`。
- `session-catalog.listSessions/getSession` 返回：
  `title`（原生标题）、`titleSource`（`session/title` | `first-user` | `workspace`）、
  `preview`（首条用户消息）、`titleDegraded`；
  按 `mtime+size` 缓存，列表刷新不重复解帧；无标题时退回工作区名并标 `workspace`。
- `client.js` 会话行：优先原生标题；没有则显示首条消息预览；副行标注来源
  （`· 首条消息` / `· 工作区名`）、短 id、时间、工作区；`title` 属性给全文。

### 2.2 分身模板与僵尸防护（`orchestrator.mjs` + `cordis.patch.yml`）

- 模板解析改为**候选过滤**：`profileTemplate` → `DSH_PROFILE_DIR` → 当前 profile →
  只接受"`node_modules/@local/dsh-fang` 真实存在"的目录；
- provision 之后**强校验** `<forkHome>/profiles/<p>/node_modules/@local/dsh-fang`；
  缺失即回收该分身并返回 `fork-bundle-unavailable`（不再留下僵尸任务）；
- 删除 `cordis.patch.yml` 中遗留的 `motherProfile: web`（僵尸根因）。

## 4. 生效方式

- 宿主侧模块（session-catalog / orchestrator / patch 配置）需**母体重启**才能加载（ESM cache + patch 层）；
- Client 半刷新页面即可看到新标题渲染；
- 重启后：控制面板会话行显示真实会话名；已存在的僵尸任务（`快速派生`，adapter http-404）请直接**归档**，
  再重新派生——新的派生会走"模板必须含 Fang"的校验，不会再产生 404 分身。

## 5. 已知边界

- 标题只从**有界帧**里取：极端情况下 `session/title` 在 64 帧之后 → 退化为首条消息/工作区名（如实标注来源）；
- `session/title` 本身可能是 DSH 的 fallback 标题（截断的首条消息），Fang 原样呈现并标注来源，不二次改写；
- 标题缓存以日志 `mtime+size` 为键；同一进程内生效，宿主重启后重建。
